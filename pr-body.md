fix(xcat-dep): dnf install xCATsn does not resolve on an EL service node

A service node reaches only BaseOS and AppStream from copycds, plus the xcat-core and xcat-dep repositories. It never reaches CRB or EPEL. Against that repo set `dnf install xCATsn` reports "nothing provides" for perl-IO-Tty, perl(IO::Pty), perl-Crypt-CBC, perl-Crypt-Rijndael, perl(Expect), perl(HTML::Form) and, per release, perl-Crypt-SSLeay, perl-Net-Telnet, perl-Digest-SHA1 and perl-Net-DNS. The provisioning then reports only "provision completed with error".

packages-manifest.conf assumes EPEL and CRB stand behind every EL target, which holds for a management node and not for a service node. The perl packages are therefore built only for rocky-10-riscv64-xcat, the one target with no EPEL. mockbuild-perl-packages.pl carries the perl-IO-Tty sources but has no %meta entry for the name, so no target can build it.

Each EL target section, x86_64 and ppc64le, now lists the perl packages BaseOS and AppStream do not carry. The %meta table in mockbuild-perl-packages.pl gains perl-IO-Tty, and its sources move to IO-Tty 1.20 with a spec. The 1.12 Makefile.PL pty probe only takes the address of each candidate function. The current toolchain drops that reference, the build defines HAVE__GETPTY on a glibc without _getpty, and IO/Tty/Tty.so fails to load. The 1.20 probe calls the function.

t/servicenode_perl_deps.t captures both halves, and .github/workflows/genesis-openembedded.yml runs it. It asserts that packages-manifest.conf carries every EL target section, that each section lists exactly the recorded perl set, that each section covers the service node set for its release, and that the %meta table can build every name. The expected sections and packages are written out in the test and the plan is counted from them, so a section or a package deleted from the manifest makes the file run fewer tests than it planned and go red. It builds no package and resolves no dependency; the build and resolution evidence is below. On the test commit seven EL target sections lack the perl set and %meta lacks perl-IO-Tty, so the test fails.

perl-IO-Tty 1.20-1 outranks the distribution copy on el8 and el9. EL8 PowerTools carries 1.12-11 and EL9 CRB carries 1.16-4, and both of those install and load correctly, so xcat-dep replaces a working package on a management node that enables CRB. This is accepted. A service node reads no CRB, so xcat-dep must carry perl-IO-Tty, and one rh<N>/<arch> tree serves both roles -- the repository cannot hold one NEVR for the management node and another for the service node. No version can both build here and lose to CRB: the only lower release in this tree is 1.12, the one that cannot be rebuilt. 1.20 is the same upstream release the distributions package, under the same license, with the same vendor paths and the same perl(IO::Tty) provides, so the higher version is an upgrade of the distribution package and not a fork. Renaming to perl-IO-Tty-xcat was considered and rejected: it needs a Conflicts against the distribution package, which turns a version comparison into a file conflict. EL10 CRB carries 1.20-7, which outranks 1.20-1, so on el10 the distribution copy still wins. perl-IO-Tty/Build-notes records this.

Verified on 2026-09-04. mockbuild-perl-packages.pl built the full perl set each EL section names, on both arches: x86_64 el8/el9/el10 and ppc64le el8 (11 packages), el9 (11) and el10 (13), every package PASS and rc=0 per target. The manifest is also the build list, so no target requires a package it does not itself build.

dnf install xCATsn resolves against BaseOS, AppStream, xcat-core and the dep repo, with no CRB and no EPEL: x86_64 el8 356, el9 422, el10 339 packages; ppc64le el8 354, el9 420, el10 338. The same command against the published dep repo, without these rpms, fails on exactly the packages this branch adds. IO::Pty->new->slave->ttyname returns /dev/pts/0 from the built perl-IO-Tty on el8, el9 and el10, on both arches.

The rpms built by hand for that proof are unsigned, which is what a manual mockbuild-perl-packages.pl run produces and is unchanged here. A CD run signs them: xcat-dep-el-cd calls mockbuild-all.pl --gpg-sign, and sign_and_index_repo runs rpmsign --addsign over every non-source rpm collected into rh<N>/<arch>, the perl set included.
